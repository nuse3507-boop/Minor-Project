# Deployment and operations

This repository supports separate static frontend, FastAPI API and persistent worker processes. Deployment was not performed. Release is blocked on OpenRouter full-schema quota qualification, human evidence evaluation, full accessibility/security review and operational validation. PostgreSQL18 and live Gemini/Groq were exercised locally; no deployment is claimed.

1. Provision PostgreSQL 16+, persistent private storage shared by API and worker, TLS termination, a private backup destination and secret management. Restrict database/storage access to service identities. The implemented storage adapter is encrypted filesystem storage; do not configure a fictitious S3 integration.
2. Install from backend/requirements.lock and the editable project, run frontend npm ci and npm run build. Serve frontend/dist through a static host/reverse proxy. Route /api to FastAPI with credentials and no caching; configure all public origins in ALLOWED_ORIGINS. Add a proxy request limit of 21 MB, body-read deadlines and connection rate limits; reject oversized/chunked bodies before application parsing. Do not serve private-data or database files. Use restrictive Content-Security-Policy for the static frontend (scripts/styles from its own built assets, object-src none, frame-ancestors none).
3. Set ENVIRONMENT=production, SECURE_COOKIES=true, DATABASE_URL, STORAGE_KEY, STORAGE_PATH, PUBLIC_URL and ALLOWED_ORIGINS explicitly. Backend startup rejects missing encryption key, insecure cookies and SQLite in production. SMTP verification must work before registration is enabled. Configure only approved provider/model pairs, verify their JSON schema support and current data-handling terms, then use synthetic documents to smoke-test each intended route.
4. Back up DB/storage/encryption key with encrypted, access-controlled retention. Test restore into isolated staging. Run python -m alembic upgrade head in backend/ before starting application and worker. Do not run downgrade on a populated deployment as a substitute for backup restoration. Prefer a forward corrective migration after release; snapshot DB and storage before changes. Check migration schema with alembic check.
5. Run uvicorn app.main:app behind TLS and python -m app.worker under a supervisor, with identical configuration and working directory. Multiple workers use PostgreSQL claims; SQLite is permitted only in explicit isolated tests. Bound process CPU/memory and isolate parsing from privileged host services. Warm tokenizer cache during deployment, avoiding first-job network downloads.
6. Monitor job queue age, lease expirations, failure codes, model usage, persistent-volume capacity and cleanup health. API responses carry request IDs and redact source/provider exceptions. The current application does not include a full metrics collector, error dashboard or calibrated SLO. Add deployment health/alert integrations before operating on sensitive real data.
7. Validate retention continuously. Worker cleanup runs every minute; APIs deny expired source scopes immediately. Audit rows contain identifiers/actions only and have a separate operator retention policy. This implementation retains those audit rows indefinitely unless an operator applies an approved policy. Disclose backup expiry and provider-side retention separately. Guest quota is account-scoped plus IP issuance throttling; deploy proxy-aware network rate limits before public exposure. Never trust arbitrary client-forwarded IP headers.
8. Test release gates: PostgreSQL migration forward/restore, two-worker concurrency, cancellation during real provider calls, provider outage and budget behavior, SMTP verify/recovery, encrypted-volume restore, parser resource exhaustion, SSRF DNS/redirect controls on the deployed network, ownership on every download/tool, keyboard and screen-reader routes at320px/200% zoom. Human reviewers must adjudicate a labeled evidence benchmark. No mock suite establishes legal accuracy.

Optional read-only MCP setup is described in README after its protocol and auth validation. Run it behind TLS on a separate private listener; never expose deployment bearer credentials in browser code or a public URL. Audit events are append-only through application surfaces; enforce database roles/backup protection if tamper-resistant operational auditing is required.
